# 📚 Journal de Bord — 2026-09-15 : CI / Backup S3 et Rollback 1 clic

## 🎯 Objectifs & Périmètre
- Déploiement de la stratégie de résilience souveraine Webomatik sur "Adopte un motard" : archivage automatique de chaque build de production vers l'infrastructure Swiss Backup S3 d'Infomaniak.
- Mise en place d'un workflow de reprise d'activité immédiate permettant un retour arrière (Rollback 1 clic) en moins de 30 secondes en cas d'incident critique ou de régression majeure en ligne.
- Implémentation d'une politique de rétention automatisée sur 12 mois glissants (snapshots intégraux sur 30 jours, puis conservation du premier snapshot mensuel sur 12 mois).

## 🛠️ Modifications & Fichiers impactés
- `.github/workflows/deploy.yml` :
  - Ajout du step post-déploiement `Backup production build to Swiss Backup S3` conditionné au succès (`if: success()`).
  - Génération automatique de `BACKUP_MANIFEST.json` consignant le nom du site, l'horodatage et le hash SHA du commit Git.
  - Compression de l'arborescence compilée `dist/` en archive `adopte-un-motard_backup_YYYY-MM-DD_HHmmss.tar.gz`.
  - Transfert AWS CLI vers `s3://webomatik-backups/adopte-un-motard/` via l'endpoint suisse `https://s3.swiss-backup04.infomaniak.com`.
  - Script Python inline utilisant `boto3` pour purger automatiquement les archives expirées selon les règles de rétention 30j / 12 mois.
- `.github/workflows/rollback.yml` :
  - Création du workflow manuel GitHub Actions déclenchable à la demande (`workflow_dispatch`).
  - Sélection automatique du dernier backup valide ou restauration d'une archive spécifique transmise en paramètre.
  - Décompression et synchronisation RSYNC directe vers l'hébergement Infomaniak sans recompilation.

## 🐛 Problèmes, Bugs & Régressions rencontrés
- **Erreur d'indentation YAML dans le script inline** : Le commit initial `f6729e1f` comportait une rupture d'indentation dans le bloc Python multi-lignes, immédiatement identifiée et corrigée par le commit `a5cfc229`.
- **Rétention des sauvegardes par défaut insuffisante** : Les sauvegardes hébergeur standard à 7 jours glissants ne permettaient pas de récupérer un état fonctionnel si une régression n'était remarquée que plusieurs semaines plus tard.

## 💡 Solutions retenues & Arbitrages techniques
- Utilisation impérative de l'option AWS CLI `addressing_style = path` requise par l'infrastructure S3 Swiss Backup Infomaniak.
- Rollback découplé du code source : le workflow de rollback restaure directement les binaires statiques archivés dans S3, ce qui élimine tout risque d'échec de build lors d'une opération d'urgence.

## ⚠️ Points de vigilance pour le futur
- Maintenir actifs les secrets GitHub `S3_ACCESS_KEY` et `S3_SECRET_KEY` associés au bucket de sauvegarde Webomatik.
