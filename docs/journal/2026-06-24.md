# 📚 Journal de Bord — 2026-06-24 : CI / Optimisation npm ci

## 🎯 Objectifs & Périmètre
- Optimisation des performances du pipeline GitHub Actions pour réduire la durée globale de déploiement.
- Remplacement du gestionnaire d'installation tolérant (`npm install`) par la commande stricte `npm ci` (Clean Install).
- Renforcement du déterminisme de l'arbre des dépendances en production.

## 🛠️ Modifications & Fichiers impactés
- `.github/workflows/deploy.yml` :
  - Modification de l'étape d'installation : exécution de `npm ci` au lieu de `npm install`.
  - Couplage avec le cache npm natif d'`actions/setup-node@v4` (`cache: 'npm'`).
- Commits associés :
  - `b4efeb65` : *perf: use npm ci in workflow to speed up package installation*

## 🐛 Problèmes, Bugs & Régressions rencontrés
- **Instabilité potentielle des builds CI** : `npm install` peut théoriquement mettre à jour des sous-dépendances selon les plages de versions (`^` ou `~`) spécifiées dans `package.json`, introduisant des régressions silencieuses en production absentes de l'environnement de développement local.
- **Lenteur d'exécution du runner** : Les calculs d'arbre de dépendances ralentissaient chaque exécution du pipeline de plusieurs dizaines de secondes.

## 💡 Solutions retenues & Arbitrages techniques
- `npm ci` supprime `node_modules` et installe exactement et exclusivement les versions figées dans `package-lock.json`, garantissant une reproductibilité binaire à 100%.
- Gain de temps mesurable sur le runner Ubuntu grâce au bypass de la résolution d'arbre de dépendances et à l'exploitation optimale du cache GitHub.

## ⚠️ Points de vigilance pour le futur
- Veiller à exécuter `npm install` localement et à committer systématiquement `package-lock.json` après tout ajout ou mise à jour de librairie externe, sous peine d'échec immédiat de `npm ci` en intégration continue.
